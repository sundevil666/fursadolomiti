# Загрузка нового сайта через FTP

`npm run build:ftp` создаёт пакет dist-ftp:

- fursa-release/ — сайт, картинки и php/send-email.php;
- .htaccess — полный новый файл для корня хостинга, заменяет старый;
- README.md — эта инструкция, её загружать не нужно.

## Загрузка

1. Резервная копия старого сайта и его .htaccess уже сохранена пользователем.
2. Загрузить папку fursa-release целиком в корень хостинга рядом с home.php.
   Это отдельная папка: старые картинки и PHP-файлы не перезаписываются.
3. После полной загрузки заменить корневой .htaccess нашим dist-ftp/.htaccess.
   В FTP-клиенте включить отображение скрытых файлов. Правила со старым файлом
   не объединяются. Не загружать .htaccess внутрь fursa-release.
4. Открыть https://www.fursadolomiti.com/ и проверить прямое открытие/обновление
   /hotels, /rental, /privacy-policy, картинки, языки и мобильный вид.

Наш сайт открывается в корне домена, не по /fursa-release/.
/home.php, /home-2.php, /index.php и /index.html временно перенаправляются на /;
/hotel-booking.php — на /hotels; /ski-rental.php — на /rental. Используется 302.
Старые параметры query сохраняются, но не переключают язык Vue автоматически.
Существующие остальные файлы, включая impressum.php, доступны напрямую.
Неизвестные адреса возвращают 404, списка файлов в каталогах нет.

## Откат

Восстановить старый .htaccess из своей копии. При необходимости восстановить
остальные старые файлы. После этого папку fursa-release можно убрать.
Одно удаление/переименование новой папки НЕ заменяет восстановление .htaccess:
старых настроек в новом файле нет.

## Что требуется от хостинга

Apache 2.4 + mod_rewrite (или совместимый сервер), разрешённый .htaccess
с Options, DirectoryIndex и rewrite (AllowOverride All). Настройки старого
файла, включая возможный выбор PHP, HTTPS и канонический домен, не переносятся.
Новый файл сам не навязывает перенаправление HTTP/HTTPS или www: это нужно
проверить на хостинге, чтобы не создать цикл за прокси.

Node нужен только для локальной сборки. База данных не нужна.
Для отправки писем используется локальный `php/email-config.php`. При первом
запуске скопировать `php/email-config.example.php` в `php/email-config.php`
и заполнить ключи EmailJS и EMAIL_RECIPIENTS. Реальный конфиг исключён из Git.
`npm run build:ftp` копирует его в `dist-ftp/fursa-release/php/email-config.php`.
FTP-пакет содержит секреты: не публиковать его в Git и не пересылать посторонним.
Загрузить папку php целиком, включая скрытый `.htaccess`: он запрещает
HTTP-доступ к конфигу. Переменные окружения сервера имеют приоритет над файлом.
PHP не читает .env автоматически. Нужны PHP с поддержкой синтаксиса 7.4+,
OpenSSL, allow_url_fopen и исходящий HTTPS к api.emailjs.com.
GET /php/send-email.php должен возвращать 405 JSON; доставку это не проверяет.
После настройки нужна отдельная тестовая заявка с проверкой писем.

Booking Südtirol / BookingExpert нужно проверить на рабочем домене, включая
реальный переход к бронированию. Геолокация в письмах может быть недоступна
без заголовков Vercel. Внешние шрифты, видео и виджеты требуют внешних сервисов.
